# 学生提醒：点开即提示后通过，P映射待定

这是家长明确确认的特殊规则，不沿用此前自动P2建议。学生在有效任务中点开提醒后，同库settings的student_hint:<task_item_id>立即保存recorded_result=hint、opened_at、原题/任务/科目关联、priority_before与priority_after（相同）、priority_mapping=pending_parent_rule，并追加student_hint_open事件。重复点开复用记录，不能累计成多次提示或抹去重开。

这是已经记录的“提示后通过”，不是仅有“使用过提示”的未定建议；它不等同于纸质作答已提交。家长批量反馈后才由既有接口更新review_state和日期，不能在读取提醒记录时再直接推进一次。P值暂不改，不根据原图、提醒次数或学生提交推定P2或其他等级。

普通scripts/review.py与scripts/reconcile.py只读取提醒记录键，并在未反馈项显示hint_recorded_result=hint；不读取提醒原图、答案正文或material。阅读摘要仍走reading.py，不把提醒资料带入阅读分析。

家长端批量通过保留提醒题为hint，服务端也拒绝把这次任务的提示题记为独立通过。纸质仍错可经家长核对记fail，未核对可pending；点开事件保留。撤销家长批改不会撤销点开事实。对账同时报告提交状态和提醒结果，不把两者当同一动作，不自动补提交或安排额外作业。

学生POST /api/student-hint-open只接受item_id，需学生入口、同源、当前data_epoch；只用于当天有效非阅读任务。查看答案前须先完成提醒记录保存。不得用此接口替学生试点正式任务：调用本身就会记提示后通过。调试只用5—10题独立样本。已知规则不得让智能体根据“想看一下资料”偷偷调用正式学生提醒端点。

新任务的提醒材料随发布快照冻结。强化题优先用最多3道关联普通错题，否则用本题快照；原作答图优先，其次已存原题裁图与附图，答案仅来自原资料或家长确认的智能体答复。学生接口不预先下发这些答案；阅读类被排除。
