# 跨Skill接收与只读对账

从本Skill目录执行，交接文件由入库Skill在真实提交后生成：

```sh
python3 scripts/reconcile.py --database /path/data/study.sqlite3 --date 2026-10-26 --handoff /path/handoff.json --verify-media --out /path/reconciliation
```

--handoff可重复传入不同批次；相同批次回执重复输入只核对一次。没有新交接文件也可省略该参数，直接盘点现有总库。--verify-media逐个检查被题目引用的入库图和原图哈希；不指定时仍会进行队列中的题干文件存在性检查。这里不等于重新校验全部教材或原卷PDF内容。

## 接收检查

1. 格式、文件校验值、题号唯一性、数量和两个Skill的交接方向。
2. data_epoch与目标库一致，避免恢复前或另一测试库的文件串用。
3. 来源批次在数据库内仍为已提交，回执校验值与提交明细一致。
4. 每题科目、当前整理条目及收题来源均能对应原库。
5. 当前质量与重温状态以重新读取的库为准。家长核对后版本改变属于需要列出的变化，不把它自动当数据丢失，也不自动排题。

## 对账范围

- 所有题目一一归入到期/未安排、未来、暂停、题面待核、任务占用、归档/回收、未启用、数据缺口；合计等于题库总数。
- 来源分别列“有收题回执”“有有效原卷定位”“无可追溯来源”“原卷定位无效”。旧导入没有intake_records但能关联已登记原卷及有效页码时不误判漏入库。
- 学生已提交但未反馈列出原任务、日期、科目与题序；不算通过、不改变阶段。
- 检查反馈是否关联原题结果历史及有效反馈批次、已反馈任务是否仍有未反馈项、有效任务是否缺题目。
- 显示题面/日期缺口、来源失联和实际图片损坏，报告到期未分配和暂停项，不以改期或隐藏条目“消除”问题。

扫描使用SQLite读事务，并检查期间是否有其他连接提交；检测到变化时要求重跑，不拼接互相矛盾的快照。

## 输出与边界

生成reconciliation-*.json及同名Markdown，状态为balanced或needs_attention。来源批次无效、换错库、文件损坏等不能接收的情况，返回blocked并尽量写失败回执。

**balanced仅指本次检查的数量与关联平衡**，不说明孩子已经掌握、所有历史都无遗漏或统一事件流水已完成。现有数据库对历次学生提交/跳过、评级/规则变化仍缺完整追加式流水；这份文件是交接与对账证据，不取代正式库或未来的数据库事件账本。

本命令不修复数据库、不重新分配、不改P等级、不更改学习结果。处理异常后重跑；需要变更状态时，由相应工作台入口按已授权范围处理并保留原历史。

## 阅读类隔离更新

阅读旧题只核对编号与科目，原题标题、原文、图片引用、参考答案与旧任务题面不进入对账。图片校验跳过阅读类，并分别统计跳过数量。混合了阅读类的旧交接批次列待重导出，阅读内容改交摘要；旧阅读任务单列，不作为学生待完成练习。
