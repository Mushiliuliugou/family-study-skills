# 错题录入与重温规则（已确认）

确认日期：2026-10-26。依据家长修改的《重温规则待确认清单》及本次“可确认”的明确指令。规则版本：2026-10-26-confirmed-v1。

## 一份分科总库，两种学习入口

唯一权威数据库沿用项目登记位置，以subject_id分科、原question_id关联。错题与“真题库”是同库的两个入口，不复制题目或图片。

这里按家长“直接通过，列入真题库，不按错题对待”的原意，将真题库用作已独立通过题的保留入口；这不代表题目来源已被核实为中考试题。来源仍按原材料记录。

## 录入

- 新题从系统实际录入日加3天首次重温；来源日期是作业/材料日期，不是重温起点。
- 学生上传默认题面待核。家长解除题面待核后，按原实际录入日加3天计算，不把审核日当作新录入日；如果已过期，保留原到期日，由家长按负荷选择。
- 同科同题图复用原题号，重复上传继续记录来源与学生原话，不重置日期或阶段。图像不同的相似题不自动合并，留待核对。
- 真题库中的同题再次录入，默认仍保留掌握状态。只有家长明确勾选“再次出错”才按当前录入日加3天重新加入重温；学生上传或智能体猜测不能触发。
- 智能体整理仍只追加待核章节、知识点和错因等建议，不代替家长确认题面、作答结果和P等级。两个Skill各司其职，不另建主库。

## 重温和批量反馈

| 家长确认的结果 | 处理 |
| --- | --- |
| 独立通过 | 立即退出错题队列，进入真题库；不再安排下次错题重温 |
| 提示后通过 | 按实际重做日依次加3、7、14、30天；到末次仍需提示时，继续按30天。任何一次独立通过即进入真题库 |
| 未通过 | 保留提示进度，默认实际重做日加1天再尝试；必要时先补基础 |
| 连续3次未通过 | 暂停普通重温，转家长处理；不自动升P0 |
| 待核对/未作答 | 不算失败，不增加提示进度，不伪造实际完成日；家长核实后再处理 |

提示后通过和独立通过清零连续未通过次数；待核对不清零。家长可以对仍需重温的题调整下次日期，但日期应晚于实际重做日。独立通过的题不采用手填下次日期。

实际重做日由家长根据纸质作答核实，可逐题填写；批改记录时间另存，二者不混用。批量反馈默认带入任务日，家长确认前应检查是否符合实际。不能登记未来重做日，不能覆盖同题已登记的相同或更晚日期；改错用撤销，保留历史。

旧数据中的重温日期与旧结果不追改，旧独立通过阶段保留作历史；新提示进度另存，避免把旧通过次数误当提示次数。旧结果不自动批量转库，因为此次确认的是规则，不是逐题新的作答事实。

## 负荷和等级

每天各科合计最多20分钟，通常参考15分钟，可以更短或不安排；无必做题数，不凑时长。每科每周两次只是有需要时的轮换参考。学校已有同类独立练习时减量。普通钟表提醒到时即停；系统只做估时，不做AI计时。超额到期题保留原日期与积压，不要求补欠账。

P0最高支持优先、P5稳定维护、U证据不足。家长确认语义如下：P0为核心先修知识反复失败并阻断当前学习；P1为核心基础未稳；P2为提示依赖或综合迁移未稳；P3为有掌握证据的偶发失误；P4为待确认掌握证据；P5为独立通过后的维护。P4/P5不设固定两次、三次或14天门槛。

家长可在题目页保存P等级与核实依据；非U须填依据。现有题默认U，智能体不自动评级。到期题优先，同类候选中按已确认P等级排序，再按原到期日；等级不增加题量，P0必要时先转讲解或求助。学生端不显示P等级。独立通过与P等级分开记录，不把一次通过擅自改写为新的家长评级。

## 使用位置与记录范围

家长：集中录入→统一题库核对→分配任务预览→纸质批改→批量反馈；真题库入口在“复习与日期”的列表分类中。重复出错可在集中录入勾选确认，也可在原题页由家长重新加入。两个入口均沿用原题号。

现有任务、重温前后状态、批量反馈、撤销、收题来源和编辑历史保留。规则版本写入新重温记录说明；升级前配置留存。全动作统一追加事件流水仍未完成，不能承诺所有历次操作均已覆盖。

不需要新账号或收费资源。规则与Skill文件位于项目内，未自动安装为全局Skill，也未给学生发布新任务。

## 调试与本次交付

日常设计调试默认随机5—10题，常用8题，只带必要题图，不复制教材/PDF或全量历史。样本库应与正式库分开，保留抽样清单；规则升级前的快照与回执由使用者保存在本机，不随Skill源码上传。

## 第4项提醒的补充约定

学生点开提醒即单独记录提示后通过；这条已确认规则不等于提前交纸质作答。家长反馈时再推进上述日期与提示阶段一次；提醒不触发P2或其他自动评级，P映射另定。详见[学生提醒协议](student-hints.md)。
